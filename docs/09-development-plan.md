## 2. 里程碑与交付门槛

以下为排期参考：熟悉相关技术的 2–3 人团队约 8–12 周，包含联调；实际工期取决于 Android 能力验证和安全审查。M0 结论未出之前不固定全后台自动同步的承诺。单人串行实现需另行估算。

| 阶段 | 参考时长 | 任务 | 退出标准 |
| --- | --- | --- | --- |
| M0 平台与密码学验证 | 1 周 | Windows 监听；Android 前台/后台读写/IME 真机；双端 AEAD/HKDF 向量 | 能力矩阵和日志证据；确定普通模式发布边界；互通解密一致 |
| M1 服务基础与身份 | 1–2 周 | 配置、迁移、数据库角色、邀请、登录/刷新/撤销、限流、保险库初始化 | 越权、重放、刷新竞态和初始化竞态测试通过；ready 真实反映状态 |
| M2 安全文字链路 | 1–2 周 | 两端登录/恢复、系统密钥保护、密文创建/拉取、本地缓存 | 双端无损互通；错误密钥/篡改拒绝；服务器查不到正文 |
| M3 实时与离线同步 | 1–2 周 | 平台适配、outbox、事务序号、WSS 提示、扫描、重试、防循环 | 丢通知/重启/长离线不丢已确认记录、不复活删除、不覆盖新剪贴板 |
| M4 历史与回收站 | 1–2 周 | 本地搜索、过滤、删除/恢复/永久删除、清理、配额 | 168h 边界、并发恢复清理、多端一致性和搜索覆盖验收 |
| M5 自托管与发布 | 1–2 周 | 私有 CA/IP、部署、备份演练、升级、签名、性能与兼容性 | 新机器按文档可部署；两端签名产物；验收矩阵证据齐全 |

## 4. 实施约束

- 每个 PR 只完成一个可验收行为，描述具体触发、结果和验证。合并前更新文档中“已实现”表；不存在的能力继续保持 false。
- 协议先行：新增字段同步修改 OpenAPI、服务端 DTO、双端模型和固定向量；跨字段语义必须有联调案例。
- 不实现“服务器代为解密搜索”来赶工；不把恢复密钥存在服务器环境变量；不把未加密队列作为临时方案上线。
- 不把 Go 领域接口当最终业务 API，实际实现增加类型化错误、上下文、事务边界和请求验证。
- 客户端不共享二进制业务库；共享的是协议、测试数据和状态机规格。双端因平台不同可以适配，但序号、AAD、错误处理不能各自定义。
- WebSocket 接入时重新设计 HTTP write timeout/升级处理和代理超时；不能盲目沿用骨架普通 HTTP 的 15 秒超时。
- 为解决确定的安全/同步风险写测试；普通静态页面不堆镜像实现的测试。功能完成后按矩阵验证，不无限扩展与本阶段无关的检查。

## 5. CI 与发布建议

后续 CI 至少有：Go fmt/vet/test + PostgreSQL 集成；Windows SDK 编译/关键状态机测试；Android Gradle 编译/lint/单测/关键仪器测试；OpenAPI 校验、schema 漂移检查、跨端向量；依赖漏洞扫描和签名产物校验。

先构建可复现开发环境，再启用 CI，不能提交一个缺少 SDK/Wrapper 的流水线却称为通过。当前验证记录与环境不足项见 [测试文档](10-testing.md)。

## 6. 发布门禁

所有 P0 需求有实际证据；Android 限制在产品页、首次引导和验收报告一致；数据库与密文审计通过；删除/恢复并发和灾难恢复演练通过；Windows/APK 可安装且签名；自托管者无需中心化账号即可启动；不存在 501 的 P0 业务接口，server-info 才能标 ready。
