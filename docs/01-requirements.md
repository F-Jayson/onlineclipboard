# 01 · 项目需求规格

## 1. 目标与成功标准

用户在电脑复制文字后，希望在同账号手机直接粘贴；反向也希望将手机文字同步到电脑。历史条目可以本地搜索、查看、再次复制、删除和恢复。用户能在自己的 VPS、NAS 或局域网主机部署服务，只需在客户端填写服务地址并登录。

目标平台：Windows 11 x64 为首发测试平台，Windows ARM64 后续；Android 10 / API 29 及以上，对当前发布系统及主流厂商逐项测试。首版只处理 `text/plain` 的 Unicode 文本，不把图片、文件路径、HTML、富文本和文件传输混入文字同步。

### 自动同步的承诺范围

| 场景 | 产品要求 |
| --- | --- |
| Windows → Windows，登录解锁且客户端运行 | 自动采集、加密上传、接收、写入剪贴板 |
| Windows → Android，应用前台有焦点且同步已启用 | 自动拉取并尝试写入系统剪贴板；成功显示“已写入本机剪贴板” |
| Windows → Android，普通应用后台 | 有执行机会时同步历史；后台写入需实测，不能保证一直即时送达；提供打开应用/通知入口点击复制 |
| Android → Windows，应用前台或用户通过系统分享文字 | 允许前台自动采集或显式分享上传，Windows 自动接收 |
| Android → Windows，从其他应用复制且本应用后台 | 普通模式不承诺自动采集；可选默认输入法模式先验证 |
| Android 默认输入法增强模式 | 用户主动设置为默认输入法后验证跨应用读取、写入及键盘展开补拉；仍不承诺进程死亡/休眠时必达 |
| 任一端离线、锁屏、密钥锁定、被强制停止 | 不宣称已写入剪贴板；恢复后同步历史，避免旧内容覆盖新复制 |

上述 Android 能力边界来自系统访问限制与后台调度限制，详见 [平台依据](11-references.md)。**若最终要求是不切换输入法、无需打开应用、所有 Android 机型后台立即可粘贴，则普通权限方案无法作为无条件可交付承诺，必须在 M0 评审后调整范围。**

## 2. 用户与使用流程

### 2.1 角色

- 普通用户：管理自己的设备、历史、回收站和同步开关。
- 自托管管理员：部署、配置注册策略、配额、账号重置、备份与升级；没有用户内容解密能力。
- 客户端设备：同一用户下独立设备 ID、会话、同步游标和密钥缓存。服务地址不同视为不同数据空间。

### 2.2 首次使用

1. 部署者完成 HTTPS 和服务启动，默认使用邀请注册，创建一次性邀请码。
2. 客户端输入 `https://clip.example.com` 或 `https://192.168.1.20:8443`；无协议输入默认补 HTTPS；显示连接测试、证书和服务版本结果。
3. 注册/登录，分配设备 ID；服务器账号创建后处于“待初始化保险库”状态。
4. 第一台设备生成内容主密钥和随机恢复密钥，展示恢复密钥，用户保存并完成抽查确认；客户端上传加密后的保险库。
5. 用户明确启用自动采集/自动写入并阅读系统剪贴板隐私说明；默认安装后不自行上传已有剪贴板。
6. 第二台设备使用同一服务地址与账号登录，输入恢复密钥，解锁保险库，初次加载历史。初次登录不把历史最新条目直接写入系统剪贴板。

### 2.3 日常使用

复制 → 本地过滤 → 本地加密持久化 → 上传 → 服务端事务保存 → 提醒其他在线设备 → 拉取 → 解密 → 更新历史 → 条件允许时写入系统剪贴板。

每个阶段显示准确状态：“待上传”“已保存到服务器”“已接收”“已写入本机剪贴板”“系统限制，点此复制”。服务端保存成功不等于手机已可粘贴。

## 3. 功能需求与优先级

P0 为首版发布门槛；P1 为首版后续增强；P2 为远期。

| ID | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-01 | P0 | 自定义服务器地址与连接测试 | 域名、IPv4、带方括号 IPv6、自定义端口；错误证书拒绝；切换地址隔离账号和缓存 |
| FR-02 | P0 | 邀请注册、登录、刷新会话、退出 | 不同账号完全隔离；退出停止采集和上传；本地默认清除账号缓存 |
| FR-03 | P0 | 设备列表、命名与撤销 | 展示平台和最近活动；撤销后该设备请求/连接均失效 |
| FR-04 | P0 | 客户端加密与新设备解锁 | 服务端数据库/日志没有正文；正确恢复密钥跨端解密；错误密钥不产生乱码条目 |
| FR-05 | P0 | 文字采集、暂停和过滤 | 精确保留空格、换行、emoji；只接受纯文本；空字符串忽略；敏感标记默认跳过 |
| FR-06 | P0 | 在线自动同步与手动复制 | 在支持的运行条件下自动；失败保留历史并提供点击复制 |
| FR-07 | P0 | 历史列表、详情、正文搜索 | 日期/设备过滤，分页加载；正文搜索在本地；显示已下载数量及覆盖范围 |
| FR-08 | P0 | 删除进入回收站 | 普通删除不直接永久删除；多端最终一致；展示到期时间 |
| FR-09 | P0 | 回收站恢复与永久删除 | 168 小时前恢复；到期立即拒绝恢复；手动永久删除须二次确认 |
| FR-10 | P0 | 7 天自动清理 | 到期禁止读取密文；清理作业每分钟运行，目标 5 分钟内完成在线物理删除 |
| FR-11 | P0 | 离线队列、断线重连、防循环 | 重试不重复创建；补偿不覆盖当前剪贴板；被删除历史不被旧设备复活 |
| FR-12 | P0 | 本地密钥保护与锁定 | Windows 用户密钥保护、Android Keystore；锁屏暂停自动写入；清理明文内存索引 |
| FR-13 | P0 | 最小自托管运维能力 | Compose、HTTPS、健康/就绪、备份恢复、迁移、版本兼容提示 |
| FR-14 | P1 | 默认输入法增强模式 | 必须先提供 M0 真机报告与可用性评审；独立开关，不默认替换用户输入法 |
| FR-15 | P1 | 批量管理、收藏、导出、可信设备扫码配对 | 补充协议和安全审查后实现；首版不展示不可用功能按钮 |
| FR-16 | P2 | 图片、文件、iOS/macOS/Linux、浏览器管理 | 不纳入当前数据协议或工期 |

## 4. 数据与业务规则

- 单条正文上限 **64 KiB UTF-8 字节**，不能用字符数代替；超过时提示并跳过，禁止静默截断。传输单请求上限 128 KiB。
- 纯空格及换行是有效文本；仅长度为 0 跳过。不调用 trim、大小写转换、Unicode 归一化或换行替换。解码非法 Unicode 时明确拒绝。
- 历史条目正文不可变；连续相同文字的通知抖动可本地短窗口去重，间隔较久重新复制可生成新条目。不得全账号按正文哈希永久去重。
- 默认每账号最多 10,000 条未永久删除记录、100 MiB 密文，回收站仍占额度。满额提示管理历史，不偷偷删除活跃条目；删除/恢复/清理不能因额度被封锁。
- 活跃历史没有默认自动过期。每个客户端完整缓存目标最多 10,000 条，正文按需解密，搜索覆盖范围必须可见。
- “删除 7 天”以服务器确认删除时间计算；离线删除在本地标“待提交”，服务器确认后才显示准确倒计时。重复删除不延长到期时间。
- 恢复不改变原创建时间、不触发自动复制；恢复后再次删除重新计算 168 小时。
- 同一账号可以登录多个设备；首版客户端同一时间只激活一个服务地址下的一个账号。
- 删除历史不会无条件清空操作系统剪贴板。它与本应用的历史、系统/第三方剪贴板历史是不同存储。

## 5. 非功能要求

下列为待验证目标，不是已测得指标。基线：2 vCPU、2 GiB RAM、SSD；100 个在线设备，10 次文字写入/秒，单条常用文本 ≤4 KiB。

| 类别 | 目标/约束 |
| --- | --- |
| 在线时延 | 两端前台或 Windows 常驻、网络 RTT ≤100ms 时，复制到目标系统剪贴板 P95 ≤2 秒；后台 Android 单独统计，不套用此指标 |
| API | 常用读写 P95 ≤300ms（不含互联网时延）；过载返回 429 与 Retry-After |
| 搜索 | 本地已加载 10,000 条常用文本，输入到结果 P95 ≤300ms；大文本按需解密 |
| 可靠性 | 服务器确认的写入有持久化事务；进程重启可重放；传输至少一次，业务幂等 |
| 安全 | TLS；客户端 AEAD；对象访问按用户过滤；日志脱敏；签名安装包；无硬编码凭据 |
| 功耗 | 不以 Android 常驻轮询/永久唤醒锁实现后台秒级同步；真机记录后台耗电和断线行为 |
| 无障碍 | 键盘导航、读屏标签、高对比、缩放；正文仅以纯文本显示，不执行链接或 HTML |
| 兼容 | 协议版本独立于应用版本；破坏性变更明确拒绝并提示升级；恢复备份后检测同步世代变化 |
| 运维 | UTC 存储、客户端本地时区展示；清理延迟、队列堆积、错误率、磁盘配额可观测 |

## 6. 首版验收示例

1. 两台 Windows 同账号在线：复制含中文、emoji、换行的文本，目标直接粘贴内容字节语义一致；重复事件不无限上传。
2. Windows 与 Android 前台同账号：同步到手机并粘贴成功；后台受限时显示真实状态，恢复前台可补齐历史。
3. Android 第三方应用分享 `text/plain`：上传后 Windows 可粘贴；普通模式不假报“后台采集已开启”。
4. 删除后双方从历史消失并进入回收站；167 小时可恢复，168 小时不可恢复；清理重试不会多次产生删除。
5. 离线设备带着旧历史上线：应用删除事件或重建缓存，不能重新上传旧缓存条目。
6. 管理员导出数据库：可看见必要元数据和密文，不能用服务端配置解出正文。
7. 在新服务器恢复备份并配置 HTTPS：两端按文档恢复连接，检测世代变化，全量校准并报告备份之后可能丢失的数据。

详细失败场景和追踪矩阵见 [测试验收](10-testing.md)。
